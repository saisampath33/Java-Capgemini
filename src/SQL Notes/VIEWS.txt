Index

Index is a database object that makes data retrieval faster
A database index works the same way as an index in text book. In text book using index a particular topic can be located faster, using database index a record can be located faster.
Without an index -> you scan every page to find a topic
with an index -> you jump straight to the page number

Table = book

Row = page

Index = book's index

Indexes created on column and that col is called index key

Types of indexes

2 Bmap

CREATE INDEX index_name

Without an index SQL does a full table scan which means it checks every row and very slow for large tables.

if index are there SQL jumps directly to matching rows much faster search, sorting and filtering

ATTRIBUTES/PROPERTIES

1.KEY ATTRIBUTE/CANDIDATE KEY: ANY ATTRIBUTES WITH WHICH WE CAN

IDENTIFY A RECORD UNIQUELY FROM THE TABLE IS KNOWN AS KEY ATTRIBUTE.

EXAMPLE:

2. NON KEY ATTRIBUTE: ALL THE OTHER ATTRIBUTES EXCEPT KEY ATTRIBUTE IS KNOWN AS NON KEY ATTRIBUTES

EXAMPLE:

3.PRIME KEY ATTRIBUTE: AMONG THE KEY ATTRIBUTES AN ATTRIBUTES IS CHOSEN TO BE THE MAIN ATTRIBUTE TO IDENTIFY A RECORED UNIQUELY FROM THE TABLE

4. NON PRIME KEY ATTRIBUTE: ALL THE KEY ATTRIBUTES EXCEPT PRÍME KEY ATTRIBUTE.

5. COMPOSITE ATTRIBUTE: IT IS COMBINATION OF 2 OR MORE NON KEY ATTRIBUTES BY WHICH WE CAN IDENTIFY A RECORED UNIQUELY FROM TABLE. [IT IS USED ONLY WHEN THERE IS NO KEY ATTRIBUTE IN THE TABLE]

6. SUPER KEY ATTRIBUTE: IT IS A SET OF ALL THE KEY ATTRIBUTES

7. FOREIGN KEY ATTRIBUTE: IT IS AN ATTRIBUTE WHICH BEHAVES AS AN ATTRIBUTE OF ANOTHER TABLE TO REPRESENT THE RELATIONSHIP

FUNCTIONAL DEPENDENCY

A RELATION EXISTS SUCH THAT AN ATTRIBUTE DETERMINES ANOTHER ATTRIBUTE UNIQUELY.

TYPES
TOTAL FUNCTIONAL DEPENDENCY
PARTIAL FUNCTIONAL DEPENDENCY
TRANSITIVE FUNCTIONAL DEPENDENCY

TOTAL FUNCTIONAL DEPENDENCY

IF ALL THE ATTRIBUTES OF A RELATION ARE DETERMINED A KEY ATTRIBUTEWE CALL IT AS TOTAL FUNCTIONAL DEPENDENCY.

PARTIAL FUNCTIONAL DEPENDENCY

A RELATION IS SAID TO HAVE PFD IF
IT CONSIST OF COMPOSITE KEY ATTRIBUTE
THERE EXISTS A DEPENDENCY SUCH THAN AN ATTRIBUTE DETERMINES ANOTHER ATTRIBUTE
WHICH IS A PART OF COMPOSITE KEY

3. TRANSITIVE FUNCTIONAL DEPENDENCY:

THERE EXISTS A DEPENDENCY SUCH THAT AN ATTRIBUTE IS DETERMINED BY ANOTHER ATTRIBUTE WHICH IS IN TURN DETERMINED BY KEY ATTRIBUTE IS KNOWN AS TRANSITIVE FUNCTIONAL DEPENDENCY

REDUNDANCY: THE REPETITION OF UNWANTED DATA IS KNOWN AS REDUNDACY

ANOMALY: THE SIDE EFFECTS THAT OCCUR DUE TO DML operation is known as anomaly.

NORMALIZATION

IT IS PROCESS OF CONVERTING A LARGE TABLE INTO SMALLER TABLE IN ORDER TO REMOVE REDUNDANCIES AND ANOMALIES BY IDENTIFYING THEIR FUNCTIONAL DEPENDENCIES IS KNOWN AS NORMALIZATION.

(OR)

IT IS PROCESS OF DECOMPOSING A TABLE INTO NORMAL FROM IS KNOWN AS NORMALIZATION

Levels of Normal Form:
1. 1st Normal Form
2. 2nd Normal Form
3. 3rd Normal Form 

1st normal Form : 
No duplicate records 
multivalued data should not be present. 

2nd normal form : 
Table should be in 1nf. 
Table should not have partial functional dependency. 

3rd normal form :
Table should be in 2nf. 
Table should not have transitional functional dependency.
